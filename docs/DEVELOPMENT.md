# Development Guide

## Prerequisites

- Node.js `^20.19.0` or `>=22.13.0`. The capture script needs Node 22+ for the global `WebSocket`.
- pnpm `9.15.9`, pinned by the `packageManager` field (pnpm switches to it automatically).
- A browser with WebGL2 and `EXT_color_buffer_float`; every desktop browser on Apple Silicon has both.
- Google Chrome for the capture script. Elsewhere than the default install path, pass `--chrome <path>` or set `CHROME_PATH`.
- ffmpeg with libmp3lame, only to cut the recorded sounds again (`pnpm sounds`); the cut files are in the repository.

## Commands

```bash
pnpm install
pnpm dev            # Vite with --host
pnpm test           # node:test over test/*.test.js
pnpm lint           # ESLint (correctness rules only)
pnpm format         # Prettier (tabs, no semicolons, single quotes, 100 columns)
pnpm format:check
pnpm build          # production bundle in dist/
pnpm preview
pnpm capture        # headless captures, contact sheet, optional bench (docs/QUALITY.md)
pnpm compare        # captures against a baseline: metrics, difference images (docs/QUALITY.md)
pnpm brand          # renders the favicon, the touch icons and the Open Graph image into public/
pnpm sounds         # cuts the recorded sounds from their CC0 sources into src/audio/sounds/ (docs/AUDIO.md)
```

`pnpm test` loads `test/support/register.mjs`, whose hooks let Node import modules written for Vite:
- extensionless relative imports;
- `.glsl` files, as their source with the `#include` chunks inlined;
- `?url` assets.

## Toolchain

- **Vite 8** builds the ES-module application. `vite-plugin-glsl` makes shader files importable and removes repeated `#include`s (`vite.config.js`). Shader chunks also carry `#ifndef` guards, because the Node hooks inline every include.
- **three** ^0.186.1, with `WebGLRenderer` (WebGL2) and GLSL `ShaderMaterial`s.
- **`postprocessing`** (pmndrs) provides the effect composer. Its `three` peer range must include the installed three version.
- **`tweakpane` 4** with `@tweakpane/plugin-essentials` builds the panel.
  - The terrain project uses lil-gui; Tweakpane is used here for its folders, color pickers and FPS graph.
  - The panel is generated from the schema, so the library stays replaceable.
- **`alea`** seeds the CPU generators.
- **`gsap`** with its TextPlugin retypes the HUD's zoom value.
- **Web Audio** plays the sound design directly, without a library ([`docs/AUDIO.md`](AUDIO.md)).
- **Kode Mono** sets the title, **JetBrains Mono** the credit line and the frame rate (both Google Fonts, SIL OFL 1.1). Their latin subsets of weight 400 are files of the repository, [`fonts/`](../fonts/) with their licenses (`kode-mono-OFL.txt`, `OFL.txt`), which Vite bundles from `style.css`; the page loads no font from a CDN.
- Plain JavaScript, no TypeScript step.

## Site Assets

- **Head** ([`index.html`](../index.html)): the title and description of **Random-eyes**, the icons, the Open Graph and Twitter cards.
- **Images** ([`public/`](../public/), copied as they are into `dist/`): `favicon.ico` (16, 32 and 48 px), `icon-192.png` and `apple-touch-icon.png` (180 px, square, opaque), all the default eye's iris seen from the front, and `og-image.jpg` (1200×630), the opening desktop scene with the frame and the HUD. [`scripts/brand.mjs`](../scripts/brand.mjs) (`pnpm brand [--samples 128]`) renders them with the app in headless Chrome, converged in photo mode: rerun it when the default eye, the opening framing or the HUD changes.
  - The iris: a still eye from the front, without the lids, lashes and tear meniscus, cut to a circle around the limbus as the camera projects it.
  - The scene: the page with its interface at 1200×630, rendered at twice the size and scaled down. A style sheet hides its texts (the title and the line about the project, the credit line, the frame rate, the HUD's readouts) and Snapshot, and the image is a screenshot of the page, not `capture()`.
- **Sounds** ([`src/audio/sounds/`](../src/audio/sounds/), imported with `?url`; the files under 4 KB are inlined): mono MP3 cuts of CC0 camera recordings from Freesound, about 100 KB, with their sources in `CREDITS.md`. [`scripts/sounds.mjs`](../scripts/sounds.mjs) (`pnpm sounds [--only <name>]`) cuts them from the manifest [`scripts/sounds.json`](../scripts/sounds.json) ([`docs/AUDIO.md`](AUDIO.md#recordings)).
- **`VITE_SITE_URL`** ([`.env`](../.env), empty by default): the site's origin, such as `https://example.com`. Social cards need absolute image URLs; Vite writes it in front of `/og-image.jpg` at build time. Set it on the host or in `.env.production.local`.

## Code Conventions

- **Modules**
  - Systems that own three.js objects are ES modules with default-export classes.
  - Pure modules (geometry, optics, sampling, params, priors, generators, color model, animation) import no three.js objects or browser state, and are tested in Node.
  - A worker is a `*.worker.js` module that wraps pure ones (ESLint gives it the worker globals); the system that owns it creates it with `new Worker(new URL(…, import.meta.url), { type: 'module' })`, which Vite bundles. The blink's frames are built so ([`src/adnexa/blinkFrames.worker.js`](../src/adnexa/blinkFrames.worker.js)).
- **Parameters**: every tunable value is a leaf of `PARAM_SCHEMA` ([`src/params/paramSchema.js`](../src/params/paramSchema.js)) with a range, unit and `kind`. Code reads values from the params object, never from duplicated constants.
  - The default values live in [`src/params/defaults.json`](../src/params/defaults.json) ([`docs/ARCHITECTURE.md`](ARCHITECTURE.md#parameters-presets-and-the-random-eye)). To change them, tune the eye in the panel, press **Export defaults JSON**, and replace the file with the download.
  - A new leaf needs only its fallback `default` in the schema; the next export writes it into the file.
- **Uniforms and defines**
  - Uniforms use a `u` prefix.
  - Constants that the CPU also needs reach GLSL as material defines, for example `MAX_EMITTERS`, `EMITTER_VEC4S`, `IRIS_ATLAS_HEIGHT`, `IRIS_LUT_*` and `DEBUG_VIEW`.
- **Shader files**
  - Shader sources live in `src/shaders/` as `.glsl` files: `*-vertex.glsl` and `*-fragment.glsl` for program entry points, plain names for chunks.
  - A chunk used by several programs gets an `#ifndef` include guard.
- **Shader rules for ANGLE-Metal**
  - GLSL loops that call heavy functions start at `ZERO`, a uniform that is always 0, so the compiler does not unroll them.
  - `irisField()` is called from loops only: march, normal, AO and shadow.
  - Hashes are integer PCG (`pcgHash()` in `common.glsl`, twin of `pcg()` in `src/random.js`), never `fract(sin())`.
  - Texture reads inside loops and branches use `textureLod`, because derivatives are undefined there and θ wraps.
  - Sampled maps are half float.
  - The RGBA32F accumulation history is read with `texelFetch`.
- **Name clashes and gotchas**
  - three defines `luminance()` for every non-raw material; the shared Rec. 709 helper here is `luma()`.
  - A `postprocessing` `Effect` must not define a method named `update`, because the effect pass calls `update(renderer, inputBuffer, deltaTime)` every frame.
- **Comments** explain constraints and non-obvious behavior only.

## URL Flags

| Flag | Effect |
| --- | --- |
| `?preset=<name>` | Starts from a preset of `src/params/presets.js` (`default`, the values of `src/params/defaults.json`, otherwise). |
| `?state=<string>` | Applies the non-default values encoded by **Copy state URL** or **Save PNG** (base64url JSON), on top of the preset. |
| `?photo=<n>` | Sets `quality.photoSamples` to `n` and starts in photo mode (frozen clock); the accumulation stops after `n` samples. |
| `?view=<name>` | Sets `debug.view`; see [`docs/RENDERING.md`](RENDERING.md#debug-views) for the list. |
| `?gui=0` | Hides the frame, the HUD, the title, the credit line, the frame rate and the panel, and makes no sound (captures). |
| `?dpr=<ratio>` | Pins the pixel ratio (0.5–2) and turns the adaptive resolution off. |
| `?debug=1` | Exposes the app object as `window.__EYE_APP__` for console debugging. |
| `?meshtree=1` | Shows the mesh tree at the left (loaded on demand, with or without the HUD): see [Mesh Tree](#mesh-tree). |
| `#debug` | Shows the panel (it is not even loaded otherwise). It follows the hash: adding or removing `#debug` on an open page shows or hides it. It also makes the skin evaluate its relief and freckles per pixel, so the panel's edits show at once; without it they are baked ([`docs/ADNEXA.md`](ADNEXA.md#skin-shading)). This part works with `?gui=0` too. |

## Controls

- Drag orbits the camera (`camera.azimuth`, `camera.elevation`). Let go while moving and the orbit coasts: its speed over the last tenth of a second decays with the time constant `controls.inertia` (0.2 s, so it coasts speed × 0.2 s), and stops at the limits of the two angles. A drag held still before letting go does not coast; a new press, a preset, a zoom or `setParams()` stops it.
- The mouse turns the view a little toward itself, as a short drag from the center would: up to a reach of azimuth and elevation at the window's edges that grows as the camera zooms out: `controls.parallax` (3° by default) zoomed in, `controls.parallaxOut` (6°) zoomed out, linear in the HUD's zoom level between (a log scale of the distance, as the wheel and the dial move; `parallaxReach()` in [`src/camera/orbitMotion.js`](../src/camera/orbitMotion.js)). The view follows it with the time constant `controls.parallaxLag` (0.4 s). It is a turn of the orbit outside the params (`CameraControls.parallax`, added by `PhysicalCamera.orbitOffset`), so it is not in the state URL. It follows only a living eye; in photo mode and on a still eye it settles back to none, so the image that accumulates is the one the params describe. Touch does not move it, and a mouse leaving the window lets it settle back.
- Right-drag moves the aperture as the HUD's aperture knob does, with its horizontal motion (the vertical one does nothing): rightward stopping down, toward the knob's + end, leftward opening up, on the knob's log scale, 525 px across its whole range, from `aperture.open` to `aperture.closed` (`CameraControls.sideDrag`, set by `main.js`). Pulled past an end it goes on, resisted, as far as the knob's own drag (`aperture.elasticity`: at most f/23.4 and f/9.6), the knob on the HUD stretching past the end, grown and lit as under its own drag (`holdAperture()`); let go there after moving, the f-number glides back to the end in 0.25 s. From an f-number off the range (a preset's) it starts at the nearer end. It sets the f-number at once and takes over from the wheel's easing. Nothing pans the target any more: Shift-drag orbits as a drag does, and `camera.targetX` and `camera.targetY` are set only by the panel, presets and the state URL.
- The wheel changes `camera.distance`, which is also the focus distance, between the HUD's zoom-in and zoom-out distances (`CameraControls.distanceLimits`); from outside them it only moves back toward them. It zooms smoothly: each step moves a target distance (steps add up on it), and the camera eases toward it every frame with the time constant `controls.zoomLag` (0.15 s; 0 jumps), on the log of the distance, so every step eases alike at any frame rate (`zoomToward()` in [`src/camera/orbitMotion.js`](../src/camera/orbitMotion.js)). A zoom button, the knob or a preset that sets the distance meanwhile takes over. The sensor height eases with it toward the one the zoom sets at the target (`CameraControls.zoomSensor`, below), with the same lag on its log, so from a framing off the zoom's curve (a reference preset) it joins the curve without a jump.
- Over the HUD's aperture knob (desktop) the wheel changes `camera.fNumber` instead, between `aperture.open` and `aperture.closed` (`CameraControls.fNumberLimits`), up the wheel stopping down as it zooms in (a notch of 100 about 0.4 stop): the same eased target as the zoom's, with `controls.zoomLag`, on the log of the f-number (`apertureWheel()`, `stepAperture()`); from outside the range it only moves back toward it, and the knob, a right-drag, a glide or a preset that sets the f-number meanwhile takes over.
- A double tap never zooms the page on touch screens (`touch-action: manipulation` on the page, `style.css`; the canvas takes every touch itself, `touch-action: none`).
- **Space** toggles photo mode when the page, not a panel control, has the focus.
- **Sound** ([`docs/AUDIO.md`](AUDIO.md)): every control sounds like a camera, over a soft glass harp that fades in slowly once the sound starts. The sound starts at the first press or key, because a browser plays none before a gesture. **M**, when the page has the focus, and the sound toggle at the end of the credit line (**sound on** / **sound off**, in the accent, underlined as the link; it blurs itself after a click) turn it off and on: off, the volume glides to zero in 0.5 s (eased out) and the sound stops once there, the glass harp pausing where it was; on, it glides back to the last level above zero the viewer settled on, and the glass harp goes on, fading in over `sound.resumeFade` s (2). The choice is kept in `localStorage` (`random-eyes:muted`); where storage fails, the sound is on and the choice holds for the page. Off, no audio context is created until it is turned on. A hidden page or a window out of focus pauses every sound (the context suspends); back, it resumes where it was. The volume slider beside the toggle sets the master volume (`sound.volume`, the panel's **master volume**, to a hundredth): a press on the handle (within 6 px of its center) keeps the point grabbed and a drag carries it; a press elsewhere glides the volume there in 0.35 s (eased out; a drag 3 px away takes over); the arrow keys step it by 0.05 and Home and End go to the ends; let go or stepped, it taps at the new level. Down to zero it turns the sound off (the toggle reads **sound off**), up from zero on again. Dragged past its right end it pulls on, as the HUD's knobs do: the volume stays full and the handle follows the pointer, resisted by their law (`elasticZoomLevel()`) up to `sound.stretch` px past the end (200 by default, less where the window lacks the room, keeping 24 px from its edge): about 100 px with the pointer 200 px past the end, 150 px with it 600 px past. The line follows by 30% of the handle's run and the sound toggle by 15%, and the glass harp plays faster the further it is pulled, up to `sound.stretchRate` (2) times at the limit (`Ambience.setSpeed()`, [`docs/AUDIO.md`](AUDIO.md#the-ambience)). Let go (or cancelled), they spring back in 0.9 s with GSAP's `elastic.out(1, 0.75)`, the handle bouncing back about a tenth of its run inside the end, and the music slows back to its own speed with them; grabbed meanwhile, the handle is held where it is. Dragged past its left end it compresses the credit line as a spring: the handle runs on left with the line held to it, and everything left of it (the credit and the sound toggle) squeezes toward the left edge to make room, up to `sound.squeeze` (half) of its width, and grows a little taller as it squeezes, about the middle of the slider's line, which stays put (on one line the capitals' middle; its width to the power −0.7, `SQUEEZE_BULGE`: 62% taller squeezed to half, a little lower when the bounce stretches it past its width; `scale` on `.credit`, the slider scaled back both ways to its size). The handle follows the pointer one to one at first, ever more stiffly (1 − (1 − t)² of the limit), and reaches the limit once the pointer has gone twice as far, sooner where the window's edge is nearer. Meanwhile the handle stays at the line's start, but the volume rises from silence to the level the spring will throw it to, its share of the limit, and the glass harp slows down to `sound.squeezeRate` (half) of its speed at the limit. Let go, the text springs back in 0.48–0.8 s with an `elastic.out` whose period shortens the more it was compressed (bouncing past its width), the handle is thrown along the line to that level in 0.56 s and the music speeds back up. At the limit the spring is armed and the handle trembles: let go there by the pointer, the volume goes to full and the handle is shot at Snapshot (a `.volume-shot` square spinning 1080° a second): where Snapshot is beside it, straight at its left side at 2200 px/s on a slight arc, which knocks it back (`.recoil`: 8 px right, 2 px up and 2.5° clockwise at once, back with the spring ease), the handle bouncing back and up; where Snapshot is above it (a phone's footer, a column), a bank shot at 900 px/s (each leg at least 0.15 s): up a little to the window's right edge (4 px short, its half), where it clicks softly and squashes (`.wall`, 0.6 × 1.3), then up into Snapshot's lower right quarter, which it knocks up, left and counterclockwise (`--recoil-x` −3 px, `--recoil-y` −7 px, `--recoil-turn` −2°), the handle dropping on down and left. Snapshot sounds its click, focus beep and shutter, and the handle falls out of the window under gravity, spinning, and only then is the photo saved (`takePhoto()`, whose rendering holds the page a moment). After 1.4 s a new handle pops up at the line's end. A press on the slider while the spring or the shot is under way does nothing. It blurs itself after a drag. The last level above zero settled on (let go, a glide's end, a key) is kept in `localStorage` (`random-eyes:volume`) over the default; the page starts there, or at zero with the sound off; a preset keeps the level. With reduced motion the glides jump.

**The frame** runs around the page, 24 px inside the window's safe area (8 px on phones and tablets): a cross of 1 px arms at each corner (14 px, 12 px on phones and tablets; white at 25%) and a dashed line along each side (an SVG pattern of `FRAME_DASH` px dashes every `FRAME_DASH_PERIOD` px, in `main.js`: 3 every 8; white at 15%). The lines run across the whole window, past the crosses, and are cut `--frame-cut` (14 px) to either side of each cross. Each side is two lines, from either window edge to the middle, the second mirrored, so the four corners look the same; the dashes are centered every 8 px from the edge and the insets are multiples of 8, so the cuts fall between dashes. On phones and tablets nothing is left beyond the crosses. At the middle of the left and right sides, 8 px inside the lines, stands a bracket (a 33 px upright with an 8 px tick inward from its middle; white at 25%, as the crosses). It is an overlay that never takes the pointer. The rest of the interface stays inside it, 16 px in (12 px on phones and tablets): `--frame-inset`, `--frame-gap` and `--ui-inset` in `style.css` place everything, the panel included.

**The HUD** ([`src/ui/hud.js`](../src/ui/hud.js)) puts the controls on a dashed circle around the eye, centered in the frame. The circle is 1.06 times the one inscribed in the box inside the frame (`HUD.scale`; 487 px on a 1600 × 1000 window, its line a little past the box at the top and bottom), or smaller where its controls would not fit, as on phones (`hudLayout()` in [`src/ui/hudLayout.js`](../src/ui/hudLayout.js)). The controls are flat, interrupted square reticles with no glass, blur or refraction. Their invisible hit areas, including the zoom slider's, are 44 px (the aperture knob's 24 px along its circle, turned with it); the zoom slider draws an 8 px square marker, the aperture knob a convex lens in profile across its circle. Angles run clockwise from the right (`HUD` in `hudLayout.js`):

- The five skin tones at the left, light highest, 60 px apart (on small circles they spread over a wider angle). The group turns along the circle to bring the pressed tone onto the horizontal (180°; `toneSteps()`, `turnTones()`), gliding there in 1 s with GSAP's `elastic.out(1, 0.75)`; the first press, a color of no tone (it stays) and reduced motion do not glide. The layout keeps every place the group can reach inside the box and clear of the zoom and Random eye (`toneReach()`); on the screens tested this costs the circle nothing.
- At the right, **Zoom in** (+) above **Zoom out** (−), 32° apart around 0° (or 160 px apart on a small circle), with the slider on the arc between them and, on a desktop HUD, the aperture knob on a circle outside it (below). **Random eye**, with a 26 px eye icon (a filled dot, the pupil, under a flattened arc, the upper lid, 18 wide and 5 high on the 24 px grid, its ends a little above the pupil's middle), sits at 33°, or at least 60 px past Zoom out; its reticle and icon stay in full white.
- The central circle keeps the frame's dashes (3 px every about 8 px, adjusted to a whole number around; white at 30%). An SVG mask cuts it around each reticle and the slider, following tone selection and zoom. The zoom slider's track, the circle between + and − (on a split HUD, the zoom's circle), is drawn again over it in full white, with the same dashes laid on the circle's own and the same cuts (`zoomTrackArc()`, `circleDashes()`; `.hud-zoom-track`); the rest of the circle keeps its transparency.
- **Portrait boxes** (phones held upright; `HUD.split`) split the HUD over two concentric circles. The central one keeps the skin tones, the pressed one at 135° (the middle of the bottom left quarter) instead of the horizontal, and Random eye at 0°, on the horizontal at the right; their hit areas may reach 10 px past the HUD's box, into the gap inside the frame (`HUD.split.overhang`), which makes the circle 10 px larger (163 px on a 390 × 844 phone). A second dashed circle, 1.45 times as wide (`zoomRadius()`), cut by the same mask, takes the zoom: the middle of the knob's track, where the portrait start (`zoom.mobileStart`, 0.5) puts it, at the bottom on the vertical, Zoom out (−) at its left and Zoom in (+) at its right, 32° apart or at least 208 px along the circle (`HUD.split.zoom.minArc`). Its buttons and knob stay 12 px above the footer (Snapshot and the credit line; `reserveBottom()`, which `main.js` calls with the footer's height); where they would not fit, the whole HUD shrinks. The tones' three arcs move in to 69% of the central radius (`HUD.split.arcs`; 112 px on a 390 × 844 phone, from 127), at the same angles; the spinning circle moves out to 118.5% of it (`HUD.split.spin`; 193 px there, from 181), its four teeth half as long (9 px); the readouts sit at 128% of it (`HUD.split.readouts`; 209 px), clear of the teeth, the zoom value 4 px further out, lower. The two segmented zoom rings stand on the vertical, where the zoom is: level with it at the middle of the zoom (`HUD.split.orbitTurn`, 90° further), turning from it as far as they turn from the horizontal elsewhere, each the other way (`HUD.split.orbitDirection`): the inner one counterclockwise as the zoom goes in, the outer one clockwise. The inner one lies at 76.2% of the central radius (`HUD.split.inner`; 124 px there, from 145), its ticks in ending about 6 px out from the tones' arcs, the outer one at 159.6% (`HUD.split.outer`; 260 px, from 228), its two ticks half as long (5.8% of its radius, 15 px). At rest every circle shows 0.1 fainter still (`style.css`, `.hud.split`): the central circle and the zoom's at 20%, the spinning circle and its teeth at 10% (30% lit), the tones' arcs at 20% (40% lit), the zoom rings at 20% (50% lit); lit layers ease their opacity with their color, in 0.4 s.
- **Active layers**: the layers of a control in use light up in the accent (`--accent`, the orange of the title's line), eased from white and back in 0.4 s (`activate()` in `hud.js`): the two zoom rings, the zoom value and the knob's marker while the zoom moves (the wheel, the buttons' glide, the knob) or the knob is held, the aperture knob's lens, the f-number and the tones' arcs it scales (on a desktop HUD) while the f-number moves (the knob, the wheel over it, its spring back, a glide) or the knob is held, the arcs as a new tone is pressed, the spinning circle at a click on Random eye, the camera angles while the orbit moves (a drag, its coasting, a glide; not the mouse parallax alone). Each stays lit a little past the control's last move (`ACTIVE_HOLD`: 0.7 s, the arcs 1.3 s after a tone and the spinning circle 1 s, past their glides); the arcs, which the tones and the aperture both light, stay lit while either does. The zoom rings' strokes take their wrapper's color (`.hud-orbit-art`, `currentColor`), so they can change color; they are opaque (the outer ring's arcs 0.75 of its ticks) and the wrappers set their opacity, 0.3 at rest and 0.8 lit. Lit, the arcs and the spinning circle also show 0.2 more, easing their opacity with their color.
- **Sway**: every layer but the central circle turns a little with the mouse (`HUD.sway`, `swayTurn()`): each arc of the tones (7°, −5.5°, 4°), the inner zoom ring (−4°), the spinning circle with its teeth (3°) and the outer zoom ring (−2°), alternating ways from the inside out, at the window's corners; the mouse's horizontal place counts fully, its vertical one half. Each follows with its own time constant (0.45–0.9 s), so they move in layers. The sway is a rotation apart from the zoom's and the clicks' (the rings' wrappers, an SVG `transform` about the center for the circle and the arcs), so it never restarts their elastic transitions. Touch does not move it, a mouse leaving the window lets it settle back, and with reduced motion it stays still.
- Inside the inner zoom ring (78% of the central radius), three solid arcs, each 36° long (2 px, white at 30%, 50% lit; `HUD.arcs`, `toneArcs()`), stand 120° apart for the light tone. Each skin tone has its own place for each arc (`HUD.arcs.tones`, a first proposal to tune); pressing a tone, or any change that heads the skin to a tone, carries each arc there independently, in 1 s with the `--elastic` bounce. A color of no tone leaves them where they are; their first placement does not animate. On a desktop HUD they also grow and shrink with the aperture, about the center, as a diaphragm opens and closes: 1.05 times their size wide open (`aperture.open`), 0.9 times stopped down (`aperture.closed`), linear in stops between (`HUD.aperture.arcs`, `apertureArcScale()`; 0.975 at the default f/15, halfway: on a 1600 × 1000 window a radius of 399 px wide open, 370 px at f/15 and 342 px stopped down, from 380 px). Past the knob's ends (a drag, or a preset's f-number off its range) they go on no further than the elastic drag can pull the f-number (`aperture.elasticity`), so the widest stay clear of the inner zoom ring's ticks. The scale is part of the SVG transform that carries their sway and the aperture knob's drag past an end (below), their line kept 2 px (`--arc-scale`), so the dash offsets of the tones' glides are untouched. A split HUD keeps them at their size.
- Between the central circle and the outer zoom ring (111% of the central radius), a dashed circle of long dashes (40 px every about 62.5 px, a whole number around; 1 px, white at 20%, 40% lit; `HUD.spin`, `spinRing()`), with four solid 18 px ticks out from it, 90° apart and at the diagonals at rest (a second circle stroked 18 px wide with four 1 px dashes, turning with it), each in the middle of a dash (the dash count is a multiple of four, the pattern centered on the ticks), turns 10° further, clockwise, at each click on Random eye: quickly (0.6 s) with the `--elastic` settle, a damped bounce drawn with `linear()` easing (browsers without it overshoot once, as `--spring`).
- Two segmented rings follow the zoom (`HUD.inner`, `HUD.outer`, `orbitRing()`), each an inline SVG drawn at the layout's size (`orbitArt()`), centered on its circle and symmetric about the horizontal: the inner ring is two lines, each a tick in (4.4% of its radius), an arc over ±31° and a tick in, one path; the outer ring two arcs over ±33.4°, with a tick out from each on the horizontal (11.65% of its radius; 76 px on a 1600 × 1000 window). Their geometry follows the radius, but their dashes and 1 px strokes keep their size in px on every screen, as every dashed line of the HUD does (`HUD.orbitDash`: 3 px every about 7 px along the arcs, 4 px every about 8 px along the outer ticks), each line starting and ending on a whole dash (`dashFit()`). Their wrappers sit on the circles' center and rotate about it. They keep the former zoom-out sizes throughout the zoom: the inner ring's radius is 89% of the central radius, the outer 140%. They may extend past the HUD's box.

Hidden at 44 px from the glyph center by default, they move inward to 28 px (`--bracket-hidden`, `--bracket-shown`; the zoom's, in their glyphs scaled 1.5, 2.67 units less than 48 and 32, the same on screen) and fade in on hover, keyboard focus or press (before the glyph and zoom-control scaling). The reticle turns with its position on the circle; icons stay upright. Reduced-motion preferences disable the decorative CSS transitions and pulse.
- Only the controls take the pointer, so drags across the rest still orbit the camera. Buttons blur themselves after a click so Space still toggles photo mode.

  - Zoom in to `zoom.in` (230 mm by default); portrait screens, less far, to `zoom.mobileIn` (426 mm by default).

The zoom-in distances are farther for it: 230 mm on the 12 mm sensor frames what 170 mm did on the 24 mm one. A preset keeps its own sensor until the next zoom.

Their reticles are always in full white, as their + and −; their brackets show on hover or while the zoom is at their end (`at-level`, set with the knob's level). A click engages the button (`engaged`): it keeps its hover look while the zoom glides to its end, also once the pointer leaves it, until `at-level` takes over, the zoom turns back or a drag takes the knob. The + and − symbols independently shrink to nothing about their center as the marker approaches (scale only, no fade, set every frame without a CSS transition), over `HUD.button` (44 px) of arc distance with a smooth ease, disappearing at overlap and returning as it moves away. This also follows elastic overshoot and snap recovery; reticles, brackets and hit areas stay present.
- **The zoom value**, on the middle of the knob's track (the bottom of a split HUD), between the spinning circle and the outer zoom ring (`zoomValueRadius()`): the camera's macro magnification at its focus distance, `magnification(camera.focalLength, camera.distance)` with three decimals and no sign (about 0.297 zoomed out, 0.593 at the desktop start, 0.917 zoomed in: the ratio on the sensor of the moment, which shrinks as the zoom goes in), as a macro lens reads its reproduction ratio. The focal length itself does not change with the zoom, which moves the camera. On a desktop HUD the f-number reads beside it, `camera.fNumber` with one decimal after a lowercase f, as lenses write it (`f/15.0`); the pair is centered where the zoom value alone sits on a split HUD, and each lights up with its own control. GSAP's TextPlugin retypes each whenever it changes, one 0.15 s tween at a time to the latest value, so a glide reads as a running counter that settles; with reduced motion it switches at once. JetBrains Mono, 12 px, `--ui-color`.
- **The camera angles**, opposite the zoom value at the same distance (left of the central circle on the horizontal); on a phone held upright (a split HUD up to 640 px wide, `style.css`) at the top right instead, their capitals level with the top of **EYES**: the camera's polar angles about the eye, azimuth then elevation in degrees with one decimal, unsigned, without the degree sign, and separated by a comma without spaces (`52.1,21.8`; `camera.azimuth` and `camera.elevation` plus the mouse parallax's turn, `CameraControls.parallax`, so moving the mouse moves them too). Retyped as the zoom value is (both are `readout()`s in `hud.js`, each text a `typedText()`). Either readout hides where it would leave the HUD's box, as on a phone held on its side.
- **The zoom knob**, a small filled square marker, slides along the zoom's circle from − (zoomed out, level 0) to + (zoomed in, level 1), over them, so the pointer always reaches it. Its place is the zoom level: where `camera.distance` lies between the screen's zoom-out and zoom-in distances, on a log scale as the wheel steps (`zoomLevel()` in `hudLayout.js`). It follows the camera every frame, during a glide too; `zoomProgress()` carries the unclamped distance during elastic drag and recovery, while `zoomLevel()` stays in [0, 1].
  - It is a slider (`role="slider"`): drag it along the arc, scroll over it, or use the arrow keys (a tenth), Page Up and Page Down (a quarter), Home and End. Dragged or keyed, it moves the camera at once and stops a zoom gliding; scrolled, it zooms as the wheel over the canvas does, smoothly (`onZoomWheel`).

  - Beyond either button, `zoom.elasticity` bounds the extension (0.12 of the whole logarithmic track by default; range 0–0.25, 0 disables it). A continuous resistance curve progressively reduces movement toward that maximum, and `camera.distance` takes that resisted level, so the view stretches too, within the camera schema’s hard bounds. The marker runs `HUD.zoom.stretch` (5) times as far: its place traces the camera's overshoot back to the pull (`pullLevel()`) and resists it with five times the elasticity (`knobLevel()`), so it follows the drag well past the button while the camera stretches no more than before, and returns with the camera. Meanwhile the brackets of the button it has passed close in on its reticle (from 32 to 16 px out, in the glyph's units, as the knob nears its farthest stretch; `--zoom-squeeze`), following the drag without a transition while squeezed (`squeezed`). Dragged back under the end they ease out as any button's do; released past it they spring back. Releasing, cancelling or losing pointer capture returns an overextended drag to the endpoint; grabbing it during the return stops the glide. The marker stays centered on the circumference, including at both snapped endpoints, and turns with the track so its sides stay tangent and radial. Hovered or dragged, it grows; clicked, it briefly pulses.

Its track runs between + and −, short enough of them that the lens, even stretched past an end as far as the elastic drag can carry it (below), stays 8 px short of their inner edges (`HUD.aperture.padding`; their 30 px reticles', 15 px from their centers along the circle), so it never runs into their reticles or brackets (`apertureTrack()`, from `aperture.elasticity`; the HUD lays itself out again when it changes); as the lens drags the zoom slider along (below), it gains on the buttons only 40% of its way past the end. Of the longest track that keeps so clear it takes 90%, about the same middle (`HUD.aperture.extent`), its stretch shrinking with it: with the default elasticity its ends are about 64 px from the buttons' centers and it is about 160 px long on a 1600 × 1000 window, 51 and 101 px on a 1280 × 720 one; without elasticity its ends would be the 8 px short of the edges themselves. Its hit area is 24 px along the circle and as long as the lens hovered. A dashed arc on that circle marks its track from end to end, under the lens (`apertureTrackArc()`: the frame's dashes, 3 px every about 8 px, 1 px, in full white as the zoom's track, a whole dash at either end). The lens cuts it as the zoom's marker cuts its circle: the same mask holds a circle of the lens's half width and `HUD.gap` (10 px) that follows the lens, so the line stops 6 px short of its sides. Dragged along past an end (below), the arc is drawn turned rather than turned by a transform, which would turn the mask's cut with it. While the lens is pulled past an end it drags the layers about it along, each turning about the center the same way by a share of the lens's turn past the end, less the farther it is (`HUD.aperture.follow`, `apertureFollowTurn()`): the dashed arc as far as the lens, rigidly, the zoom slider as a block by 0.6 (+ and −, their cuts in the circle, the zoom's knob, its white track and the dashes of the circle they lie on, which turn by a dash offset so the cuts do not turn twice; `zoomTrackArc()`'s `turn`), the tones' three arcs as a block by 0.6 too (a rotation in their transform, on top of their sway, so the dash offsets that carry them to a new tone's places glide on undisturbed, even mid-glide), and Random eye by 0.24. They come back with the lens as it springs back. On a 1600 × 1000 window, the lens about 64 px past an end at most, the arc follows as far, the zoom slider about 37 px, the tones' arcs about 29 px and Random eye about 15 px. Its place is `camera.fNumber` between `aperture.open` (f/10, by −, level 0) and `aperture.closed` (f/22.5, by +, level 1), which put the default f/15 halfway, their geometric mean, on a log scale, as f-stops run (`apertureProgress()`, `apertureFNumber()`); it follows the f-number every frame, and an f-number off the range (a preset's) leaves it at its end. The layout keeps its whole track inside the box (`hudLayout()`'s `aperture` option).
  - It is a slider (`role="slider"`, the f-number as its value text) built as the zoom knob is (`trackKnob()` in `hud.js`): drag it along the circle, scroll over it (the wheel above), or use the arrow keys, Page Up and Page Down, Home and End. ### Mesh Tree

With `?meshtree=1` a second Tweakpane panel, **Mesh tree**, lists the main scene's graph at the left ([`src/debug/meshTree.js`](../src/debug/meshTree.js)): one folder per object, titled with its name and type, its children nested inside. Above the tree, read twice a second: **draw calls**, those of the last frame rendered over every pass (shadow maps and coverages, the scene, the depth of field, the dust and the effects; `FrameStats.drawCalls`, so a converged photo keeps its last frame's), and **scene vertices**, the vertices of the meshes drawn, the shadow proxies included (a hidden mesh, or one in a hidden group, leaves the count). The shadow proxies of the lids and the lashes (`LidsShadow`, `LashesShadow`, [`docs/OPTICS.md`](OPTICS.md#key-light-shadow)) are in the tree: drawn only in the shadow passes, hiding one takes its shadow away; the passes draw them with their own material, so their wireframe does not show. Every object has **visible** (`Object3D.visible`: hiding a group hides what it holds) and every mesh **wireframe** (on all its materials, which the app never swaps, so it holds through rebuilds and debug views) and **vertices**, its geometry's vertex count (read once a second, since rebuilds replace the geometry). Each edit calls `EyeApp.refreshScene()`: the soft coverages are made again from the casters now shown (hidden lids or lashes drop their shadows, the floor's included) and the image restarts. The tree is built once, from the graph as it is at start-up. `SplitShadingBlock`, which the scene pass shows only for its own draws (`userData.managed`), is listed collapsed with both toggles disabled. The panel sits below the title (at the top without the HUD) and above the credit line, and scrolls when it outgrows the viewport (`.mesh-tree`, `style.css`).

## Console API

`window.__EYE__` always exposes:

| Member | Purpose |
| --- | --- |
| `params` | The live params object (change it through `setParams`). |
| `getAccumulation()` | `{ samples, target, converged }`. |
| `getRenderStats()` | Frame telemetry and the adaptive pixel ratio state. |
| `getState()` | The non-default values as a `?state=` string. |
| `getParams()` | A deep copy of the params. |
| `setParams(overrides)` | Ends a running transition, applies a deep partial override at once, rebuilds, and returns the unknown paths. |
| `transitionTo(params, duration)` | Glides to a full params object over `duration` seconds ([`docs/ARCHITECTURE.md`](ARCHITECTURE.md#transitions)). |
| `getTargetParams()`, `isTransitioning()` | The params a running transition is heading for (the current ones otherwise); whether one runs. |
| `capture()` | The current accumulated image as a PNG data URL (a living eye keeps no frame: it renders one first). |
| `toggleFrozen()`, `isFrozen()` | Photo mode. |
| `blink()`, `isBlinkReady()` | Starts a blink of a living eye now; whether the blink's frames are built (until then the lids stay open, and `blink()` returns `false`). |
| `measure(frames)` | Interactive frames back to back; resolves with frame statistics. |
| `measureSync(frames)` | The same, each frame finished with a synchronous read; returns mean, median, minimum and maximum ms. |
| `getCompileMs()` | The time spent compiling programs at start-up. |
| `setSkinBaked(baked)`, `isSkinBaked()`, `getSkinBakeMs()` | The skin's relief baked or per pixel (what `#debug` switches; the next hash change sets it again); the last bake's time. |
| `getEyeGeometry()` | `{ apexZ, focusDepth }`. |
| `getPresetNames()`, `getPresetInfo(name)` | Preset names, labels and reference photographs. |
| `loadPreset(name, duration)`, `randomEye(ancestry, seed, duration)` | Glide to a preset or to a random eye, as the panel does; `randomEye` returns the sampled features and the color shade. |
| `zoom('in' \| 'out', duration)` | Glide the camera as the HUD's zoom buttons do, over `zoom.duration` unless given. |
| `getZoomLevel()`, `setZoomLevel(level)` | The bounded zoom level (0 zoomed out, 1 in); setting it moves the camera at once. The HUD also supplies small resisted values outside [0, 1] while dragging elastically. |
| `getApertureLevel()`, `setApertureLevel(level)` | The bounded aperture level (0 at `aperture.open`, 1 at `aperture.closed`, on a log scale); setting it sets `camera.fNumber` at once, as the HUD's aperture knob does (also past the ends, while dragging elastically). |
| `skinTone(name, duration)` | Glide `skin.color` to a tone of `src/params/skinTones.js`, as the HUD's skin tones do; `false` for an unknown name. |
| `getSoundStats()` | With the interface only (not `?gui=0`): the audio context's state (`none` before the first gesture), whether the sounds are decoded, the mute, the pause (a hidden or unfocused page), each sound's play count (with the glass harp's glasses), the master's peak and RMS (dBFS) since the last call, and `musicSpeed`, the glass harp's speed (1, more while the volume slider is pulled past its end) ([`docs/AUDIO.md`](AUDIO.md#engine)). |

## Debugging Notes

- Shader compilation errors appear in the browser console, not in `pnpm build`. They also make `pnpm capture` fail.
- A uniformly grey or black image usually means a NaN or an alpha problem.
  - Check the raw scene with `?view=normals`.
  - Then read pixels through `window.__EYE_APP__`; the accumulation history is `app.post.accumulation.history`.
- A living eye restarts the accumulation every frame and keeps none of them in the history. Press Space, or turn `animation.enabled` off, to let the image converge.
- Once `quality.photoSamples` samples are accumulated, the loop stops rendering and the canvas keeps the last image. Any change restarts it.
- `?view=iris-steps` shows the march cost per pixel: red where it hits the step limit. The other `iris-*` views isolate the field, its normals, AO and atlas.
